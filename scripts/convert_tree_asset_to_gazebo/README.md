# convert_tree_asset_to_gazebo

Convert a prepared private Blender tree asset into a Gazebo model directory.

This tool is intentionally not tied to any Blender add-on. Create or edit the tree locally in Blender, apply or realize procedural content when needed, save a prepared `.blend`, then run this converter.

## Basic Usage

```bash
cd src/forest_map_generator

blender --background --python scripts/convert_tree_asset_to_gazebo/convert_tree_asset_to_gazebo.py -- \
  --input /path/to/assets_private/orange_tree_mikan_01_prepared.blend \
  --model-name orange_tree_mikan_01 \
  --output-dir /path/to/models_private/orange_tree_mikan_01 \
  --origin-mode bottom_center \
  --collision-mode thick_branch_cylinders \
  --collision-min-radius 0.04 \
  --collision-max-branch-height 1.8
```

Expected output:

```text
models_private/orange_tree_mikan_01/
├── model.config
├── model.sdf
└── meshes/
    ├── tree_mesh.obj
    ├── tree_mesh.mtl        # if generated by Blender
    ├── tree_collision.stl
    └── textures/            # optional, when --copy-textures is used
```

Use the generated model name in QGIS / GeoJSON placement:

```text
tree_type = orange_tree_mikan_01
```

## Blender Scene Preparation

Recommended preparation before conversion:

- Use meters as the unit scale.
- Put the trunk base / ground contact point near `z=0`.
- Convert or apply add-on/procedural objects to real mesh objects when possible.
- Realize Geometry Nodes or particle instances if they should appear in the exported mesh.
- Optionally create a `visual` collection for render geometry.
- Optionally create a `collision` collection for simplified custom collision geometry.
- Keep private `.blend`, purchased assets, and textures outside the repository.

If no `visual` collection exists, the converter exports all visible mesh-like objects except camera/light objects and objects in the `collision` collection.

## Orientation

Blender and Gazebo should both use the same coordinate convention: X/Y are horizontal and Z is up. OBJ visual export uses Blender 5.x `bpy.ops.wm.obj_export` and explicitly requests `forward_axis=Y, up_axis=Z` when those options are available.

The converter logs visual bounds before export:

```text
Visual bounds before export:
  min = (...)
  max = (...)
  size = (...)
  height_z = ...
```

If the model appears sideways, check the input Blender model rotation, the printed OBJ axis settings, and that `model.sdf` does not contain a hidden visual pose rotation.

## Collision Modes

The converter always writes `meshes/tree_collision.stl`.

Collision priority is:

1. `--collision-file /path/to/tree_collision.stl`
2. Blender collection named by `--collision-collection` (`collision` by default)
3. `--collision-mode thick_branch_cylinders`
4. `--collision-mode trunk_cylinder`
5. Other generated modes

- `trunk_cylinder` (default): simple trunk cylinder, suitable for orchard navigation.
- `thick_branch_cylinders`: trunk plus coarse cylinders for low thick Curve branch segments. Leaves, fruits, thin twigs, and upper crown branches are excluded by name/radius/height filters.
- `bounding_box`: box covering the visual bounds.
- `bounding_cylinder`: cylinder covering the visual horizontal extent and height.
- `visual_decimated_optional`: decimated duplicate of visual meshes; can be expensive in Gazebo.
- `--collision-file`: copy an existing STL directly to `meshes/tree_collision.stl`.

For best control, create a Blender collection named `collision` containing simplified trunk/main-branch geometry. The converter can export that collection as `tree_collision.stl`.

## Origin Modes

- `bottom_center` (default): visual bounds bottom becomes `z=0`, and visual bounds center becomes `x=0, y=0`.
- `keep`: keep object transforms as authored.
- `cursor`: use the Blender scene cursor as Gazebo model origin.
- `named_empty`: use an Empty named by `--origin-empty-name` (`TREE_ORIGIN` by default).

## Resource Path

When outputting to a private directory outside the ROS package, add the parent directory to the Gazebo resource path:

```bash
export IGN_GAZEBO_RESOURCE_PATH=$IGN_GAZEBO_RESOURCE_PATH:/path/to/models_private
```

For newer GZ Sim environments, use:

```bash
export GZ_SIM_RESOURCE_PATH=$GZ_SIM_RESOURCE_PATH:/path/to/models_private
```

Blender is needed only for conversion. Once the Gazebo model directory exists, the Docker / Gazebo runtime does not need Blender.

## Notes

- Visual output is OBJ only: `meshes/tree_mesh.obj`.
- DAE is not used for this workflow because Blender 5.x may not provide Collada export.
- `--copy-textures` copies external image texture files referenced by material nodes into `meshes/textures/` when possible, but texture-heavy assets may still need manual material/path checks.
- `--dry-run` opens the input and reports export decisions without writing files.
